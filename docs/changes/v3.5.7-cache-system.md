# v3.5.7 缓存系统实现记录

## 日期

2026-01-24

## 变更原因

原始实现中 `/gift/attention` 端点直接调用外部 API，完全没有缓存机制。同一数据被重复请求时每次都调用外部服务，导致：
- 20 场会话需要 40 次 attention API 调用
- 页面加载耗时 30-60 秒
- 外部 API 被频繁调用，服务器负载高

## 涉及文件

- `rust_backend/src/main.rs` — 核心缓存逻辑实现
- `frontend/src/api/index.js` — 前端 API 支持 union 参数

## 涉及模块

- 后端缓存管理器（CacheManager）
- Attention 数据缓存
- 直播会话数据缓存
- 粉丝数计算优化
- 前端懒加载模式

## 实现内容

### 1. 缓存管理器

- 使用 LRU 算法管理缓存条目
- 5GB 大小上限
- 仅对过去月份数据缓存，当前月份不缓存以确保实时性
- 自动清理旧条目
- 缓存命中率统计

### 2. Attention 数据批量缓存

- 批量获取单个主播单个月份全部 attention 数据
- 缓存键：`attention_{union}_{room_id}_{month}`
- 上月数据永久缓存
- 当月数据 1 小时有效，1:30-2:00 可刷新

### 3. 懒加载模式

- `/gift/live_sessions` 默认不计算 `new_fans_count`
- `/gift/live_sessions_with_fans` 完整计算模式
- `/gift/session_fans_change` 单个会话按需计算

## 性能提升

| 场景 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 首次加载（20场会话） | 42次API，~30秒 | 3次API，~3-5秒 | 10倍 |
| 重复访问同月同主播 | 42次API，~30秒 | 0次API，< 100ms | 300+倍 |
