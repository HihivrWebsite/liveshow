# 缓存架构

当前策略对应 v4.7.17，完整接口和指标说明见[共享上游缓存](../features/upstream-cache.md)。

## 请求路径

浏览器 → 10 秒 Gift HTTP 响应缓存 → handler → 共享 VR/PSP 源数据缓存 → 上游 API。

- HTTP 层按完整路径和查询缓存，保持 512 条/64 MiB、单响应 16 MiB、同键并发合并、错误缓存及 `X-Gift-Cache` 诊断头。
- 源数据层按来源、上游接口、房间和月份缓存，展示筛选与调用入口不分裂缓存键；VR/PSP 完全隔离。
- 源数据内存层采用 512 条/128 MiB 的 LRU，容量为序列化字节估算，不是整个进程内存限额。
- 历史数据及当月场次/Attention 使用 `cache_data/upstream_v1/` 持久化。旧目录保留但不读取，避免沿用缺少来源和明确有效期的缓存。

## 有效期

| 源数据 | 非空结果 | 成功空结果 |
| --- | --- | --- |
| 当前榜单（默认或显式月份） | 5 分钟 | 60 秒 |
| 当月场次、Attention | 下一个本地时间 01:30 | 60 秒 |
| 历史月份榜单、场次、Attention | 24 小时 | 1 小时 |
| SC | 仅外层 10 秒 | 同左 |

有效期在访问时检查；没有定时轮询业务接口。上游错误不进入源数据缓存，外层仍缓存错误 10 秒。每日规则以抓取当天的刷新边界计算，过期条目不能在下一次午夜重新有效。

## 前端

首页和详情无定时业务轮询。对比组件使用组件内存 Map，TTL 2 小时，没有文档旧版所称的 localStorage 1 小时缓存。缓存统计请求不触发上游业务请求，头像使用内嵌默认图。

“刷新/补全”串行调用服务端清理，成功后清空全部组件范围缓存并重新加载选中范围；清理失败保留旧数据并提示错误。

## 清理与一致性

有效 `POST /cache/clear` 同时清理选中源的内存、磁盘及外层响应缓存。源缓存清理等待在途读写完成，外层通过 generation 防止旧响应回写；成功返回后下一次请求不能读回被清理的磁盘条目。参数无效不清缓存，磁盘清理失败不能返回成功。

## 监控

`/cache/stats.upstream_cache` 按来源/接口及入口报告实际上游网络尝试、错误、空结果、各层命中和部署版本/进程信息。顶层兼容字段统计全部源数据缓存，内存大小和条目不再与磁盘大小取最大值混用。

外层 `gift_response_cache.misses` 只代表 handler 执行次数。计算回源速率应对同一进程的 `upstream_requests` 做差分；生产日志只有 IP 时无法排除同机其他调用方。共享缓存没有全局出站限流能力。
